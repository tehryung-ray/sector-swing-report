# 섹터 스윙 리포트

미국 장 마감 후 섹터 흐름을 분석해, 한국 장 시작 전에 국내 섹터 ETF 스윙 후보를
정적 웹페이지로 띄우는 자동화 리포트.

## 실행

```bash
pip install -r requirements.txt
python -m pipeline.main
python -m http.server 8731 --directory docs   # http://localhost:8731
```

| 환경변수 | 용도 |
|---|---|
| `GEMINI_API_KEY` | 뉴스 성향 분류를 Gemini로 승격 (없으면 키워드 사전으로 폴백) |
| `GEMINI_MODEL` | 기본 `gemini-2.5-flash-lite` |
| `SKIP_NEWS` | 뉴스 수집 생략 (로컬 빠른 실행용) |
| `TELEGRAM_BOT_TOKEN` | 개장 점검 알림용 봇 토큰 (없으면 화면 출력만) |
| `TELEGRAM_CHAT_ID` | 알림 받을 대화방 ID |
| `DRY_RUN` | 개장 점검을 전송 없이 결과만 확인 |

## 자동 실행

| 워크플로 | 시각(KST) | 하는 일 |
|---|---|---|
| `daily.yml` | 06:50 (+07:50 재시도) | 리포트·복기 생성 |
| `openbell.yml` | **09:10** | 개장 후 주문 점검, 손 쓸 일 있으면 텔레그램 알림 |

**GitHub 크론은 신뢰할 수 없다.** 실측으로 리포트 06:50 예정이 누락되고
개장 점검 09:10 예정이 13:35(+266분)에 돌았다. 공식 문서도 "부하가 높으면 일부 대기 작업이
버려질 수 있다"고 명시하며 유료 플랜으로도 해결되지 않는다.
그래서 **창을 넓게 잡아 여러 번 시도**한다(리포트 7회, 개장점검 5회).
먼저 성공한 실행이 일을 하고 나머지는 스스로 빠진다.

24시간 켜진 PC가 있다면 [ops/](ops/README.md) 의 로컬 스케줄러를 함께 걸어
이중화하는 것을 권한다. GitHub 쪽을 끄지 않아도 중복되지 않는다.

개장 점검은 세 가지를 판정한다.

| 상황 | 판정 | 해야 할 일 |
|---|---|---|
| 시가 < 취소선(손절가) | 셋업 무효 | 예약주문 취소 |
| 저가 ≤ 진입가 | 체결됐을 것 | 익절·손절 주문 걸기 |
| 진입가까지 안 내려옴 | 미체결 | 없음 |

**할 일이 없으면 보내지 않는다.** 알림이 왔다는 것은 손을 써야 한다는 뜻이다.
단, 09:05 이후에 전 종목 시세를 못 받으면 그 사실을 알린다 —
조용히 넘어가면 취소해야 할 주문을 놓친다.

로컬 확인: `DRY_RUN=1 python -m pipeline.check_open`

## 구조

```
config/     미국 섹터 유니버스, 한국 ETF 매핑 (기획서 2단계 "지도")
pipeline/   수집 → 랭킹 → 가격산출 → JSON
docs/       GitHub Pages 루트. JSON을 읽어 렌더하는 정적 페이지
cache/      OHLCV parquet. 데이터 소스가 죽어도 리포트가 나오게 하는 안전망
            (git 미추적 - CI 에서는 actions/cache 가 보관)
```

## 알아둘 것

- **모든 진입가는 전일 종가 이하**다. 아침 7시에 보고 장전에 예약주문을 거는 워크플로라,
  현재가보다 위의 지정가 매수는 조건 충족이 아니라 개장 즉시 시가 체결이 되기 때문이다.
- 한국 ETF 가격은 **전 거래일 종가 기준**이다. 오전 7시엔 당일 시세가 존재하지 않는다.
- 뉴스의 긍정/부정은 참고용이다. 판단 근거는 시세로 계산한 가격 신호다.
- ETF 종목코드는 매 실행마다 실물 상장목록과 대조한다. 불일치 시 리포트를 만들지 않고 실패한다.

자세한 설계와 산출식은 [PLAN.md](PLAN.md) 참고.
